# ASCE-CoC 架构说明

本文档说明 ASCE-CoC 的设计取舍、模块边界与数据模型。面向两类读者：

* **使用者**：想知道系统怎么运作、数据存在哪里、参数怎么调。
* **扩展者**：想替换推理服务、改造认知链、接入自己的语料，或在系统之上做分析。

---

## 一、设计目标与原则

### 目标

多智能体社会仿真最常见的问题不是"跑不起来"，而是**跑完了解释不清**：
研究者看到群体层面的立场分布变化，却无法回答"是哪些智能体、在哪一轮、因为看到了什么、
经过了怎样的判断，才导致了这次变化"。

ASCE-CoC 把**推理过程本身**作为一等数据来设计，因此三个目标贯穿全部模块：

| 目标 | 具体落实 |
|---|---|
| 推理可观测 | 每个认知节点独立落库，可统计、可引用、可回溯 |
| 归因可追溯 | "看到的 ID → 思考原文 → 工具调用 → 结果"四段都在同一行记录 |
| 运行可复现 | 固定种子、显式仿真时钟、版本化 schema、一次运行一个自包含库 |

### 原则

1. **认知用自然语言表达，但保留结构**。不给认知设枚举值域，但要求推理带节点标记，
   于是既有可读的原文，也有可统计的结构。
2. **不让模型自我监督，而是用结构约束它**。需要保证"先想后做"时，
   做法是让第一次调用拿不到工具，而不是提示模型"请先思考再行动"。
3. **失败要显形，不要被兜底掩盖**。节点缺失、工具调用被拒、输出被截断，
   全部如实记录，让健康度指标反映真实情况。
4. **写入路径不可互相拖累**。认知链数据与平台数据的写入失败必须各自可控。

## 二、系统架构

### 2.1 模块职责

```
sim/
├── chain/                    认知链（与平台无耦合，可独立测试）
│   ├── spec.py               维度与节点的定义、三档密度、两阶段切分
│   └── prompts.py            两阶段 prompt 模板、节点输出契约、鲁棒解析器
│
├── tools/                    动作工具层
│   ├── actions.py            18 个动作的 tool schema + 参数校验 + 类型转换
│   └── executor.py           幂等执行器 + 上下文守卫 + 内容质量守卫
│
├── platform/                 仿真平台（不感知 LLM）
│   ├── schema.sql            唯一权威 schema（18 张表）
│   ├── db.py                 连接、建表、幂等迁移、元信息
│   ├── clock.py              仿真时钟：tick → 沙盒时间戳
│   ├── recsys.py             推荐打分（预取式，无逐条查询）
│   └── core.py               平台 API：内容、互动、推荐、可见性
│
├── agent/
│   ├── llm_client.py         多端点异步客户端：并发、tool call、重试、统计
│   └── agent.py              单轮完整因果链：刷流 → 两阶段推理 → 工具循环 → 落库
│
├── persistence/
│   └── store.py              认知链落库（宽表 + 两张明细表）
│
├── live/                     实时监控页
│   ├── server.py             HTTP + SSE（独立进程，只读数据库），并渲染打印页
│   └── static/               前端（无外部 CDN 依赖）
│
└── simulation.py             主循环：装配、逐轮调度、统计与收尾报告
```

**依赖方向是单向的**：`chain` 与 `tools` 不依赖 `platform`；
`platform` 不依赖 `agent` 与 LLM；`agent` 组合前两者。
因此认知链可以在没有平台、没有仿真的情况下单独测试
（`scripts/test_chain.py` 就是这样做的）。

### 2.2 单轮数据流

```
                      ┌──────────────────────────────┐
   主循环（每 tick）   │ 1. 发话题帖（作者按兴趣匹配）  │
                      │ 2. 重算推荐表                 │
                      │ 3. 按激活率抽活跃智能体        │
                      └───────────────┬──────────────┘
                                      │ 并发
        ┌─────────────────────────────▼─────────────────────────────┐
        │ 单个智能体的一轮                                           │
        │                                                           │
        │  refresh() ──→ 推荐流 + 评论树（注册为"可见集合"）          │
        │       │                                                   │
        │       ├── 收集本轮定向互动                                 │
        │       │                                                   │
        │       ├── 渲染上下文：画像 / 话题背景 / 记忆 /             │
        │       │   平台现状 / 推荐流 / 定向互动                      │
        │       │                                                   │
        │       ├─ 第 1 次 LLM【无工具】→ 情绪·情感·思维·立场         │
        │       │        ↓ 原文作为前提传入下一次调用                 │
        │       ├─ 第 2 次 LLM【18 个工具】→ 观点·意图·一致性 + 动作  │
        │       │        ↓                                          │
        │       └─ 工具循环：回灌执行结果，可继续调用（有次数上限）    │
        │                ↓                                          │
        │        落库：agent_turn + agent_chain_step + agent_tool_call│
        └─────────────────────────────┬─────────────────────────────┘
                                      │
                      ┌───────────────▼──────────────┐
                      │ 未激活智能体同样留痕（基线）  │
                      │ 写 tick 统计                 │
                      │ 监控页经 SSE 推送             │
                      └──────────────────────────────┘
```

未激活的智能体也会写一条 `agent_turn`（`is_active = 0`）。
这是必要的：研究"激活"本身的影响时，必须能区分"这一轮没被激活"与"这一轮不存在"。

## 三、认知链设计

### 3.1 六个维度

| 维度 | key | 主理论 | 在刻画什么 | 时间尺度 |
|---|---|---|---|---|
| **情绪** | `emotion` | 普拉切克情绪之轮 + 罗素情绪环形模型 | 由当下刺激直接触发的即时反应 | 秒级–分钟级 |
| **情感** | `mood` | 积极与消极情感模型（PANAS）+ 贝克认知疗法 | 跨轮次稳定的长期情感底色 | 天级–周级 |
| **思维** | `thinking` | 双重加工理论（System 1 / System 2） | 信息处理风格与认知资源投入 | 单次判断内 |
| **立场** | `stance` | 道德基础理论（MFT）+ 右翼威权主义（RWA） | 价值取向层面的定性定位 | 月级，慢变 |
| **观点** | `opinion` | 社会判断理论 + 态度强度理论 | 对具体对象的认同强度 | 单次接触内可变 |
| **意图** | `intention` | 计划行为理论（TPB） | 行动倾向 | 单轮内形成 |

**立场与观点的分工**是这套维度划分的核心：

> **立场**回答"我站在哪一边"——定性、离散、变化慢，是观点的吸引子。
> **观点**回答"我对眼前这件事认同到什么程度"——连续、可变、针对具体对象。

两者的时间尺度不同（月级 vs 单次接触），因此必须分开建模。若把它们合并成一个
"态度"标量，就会丢掉"长期立场稳定、但具体观点被某条强证据短时推离"这类现象，
而这恰好是认知与行为出现张力的主要来源。

### 3.2 节点定义（完整 17 个）

| 维度 | key | 节点 | 理论依据 | 追问什么 | 应产出什么 |
|---|---|---|---|---|---|
| 情绪 | `E1` | 刺激评估 | 评价理论 | 这条内容对我的目标、利益或价值意味着什么 | 威胁 / 机会 / 无关，并说明关联点 |
| 情绪 | `E2` | 即时情绪 | 普拉切克情绪之轮 | 八种基本情绪里哪几种被触发，强度如何 | 具体情绪（可多个）+ 强度 + 理由 |
| 情绪 | `E3` | 效价与唤醒 | 罗素情绪环形模型 | 我的情绪落在环形的哪个位置 | 效价方向 + 唤醒高低 + 对判断的推力 |
| 情感 | `M1` | 情感底色 | PANAS | 抛开此刻刺激，我长期的情感倾向是什么 | 正/负性倾向，及此刻放大或抑制了什么 |
| 情感 | `M2` | 认知重构 | 贝克认知疗法 | 第一时间冒出的自动想法经得起检验吗 | 自动想法 → 证据检验 → 重构结果 |
| 思维 | `T1` | 加工模式 | 双重加工理论 | 这件事值得动用分析系统吗 | System 1 还是 System 2，及其偏差或优势 |
| 思维 | `T2` | 证据与权衡 | 证据累积与权衡 | 我能调用哪些知识，有哪些冲突证据 | 证据清单 + 权重 + 承认的不确定处 |
| 立场 | `S1` | 道德基础 | 道德基础理论 | 哪几条道德基础被触动，方向如何 | 被触动的道德基础及其推力方向 |
| 立场 | `S2` | 合法性判断 | 右翼威权主义 | 权威、传统、群体共识应被尊重还是质疑 | 态度 + 理由 + 该倾向的强弱 |
| 立场 | `S3` | 立场定位 | 态度形成 | 综合以上，我站哪一边 | 一句自然语言立场 + 是否松动 |
| 观点 | `O1` | 接受与拒绝纬度 | 社会判断理论 | 哪些说法在我可接受范围，哪些越界 | 接受区 / 拒绝区 / 不表态区，及本条落点 |
| 观点 | `O2` | 态度强度 | 态度强度理论 | 我的确定性、重要性、可及性有多高 | 三者各自的强弱 + 是否容易被说动 |
| 观点 | `O3` | 观点变化方向 | 说服与同化对比 | 我的观点固化了、松动了还是被反转 | 变化方向 + 造成变化的那个点 |
| 意图 | `I1` | 态度 | 计划行为理论 | 我怎样评价"去做这个行为"本身 | 正面/负面评价 + 理由 |
| 意图 | `I2` | 主观规范 | 计划行为理论 | 我感知到的群体期待有多大、方向如何 | 压力强度与方向 + 对行为的影响 |
| 意图 | `I3` | 感知行为控制 | 计划行为理论 | 我有没有能力与条件做到 | 掌控程度 + 现实约束 |
| 一致性 | `Z1` | 认知链一致性 | 认知一致性理论 | 从情绪到意图这条链自洽吗 | 是否自洽；冲突时指明维度并交代服从了哪一边 |

节点只描述**要做什么推理**，不规定**输出哪个枚举值**。
这是有意的：把认知压缩成有限标签，会让推理退化成从给定选项里挑一个，
也让"模型真的这么想"和"系统替它填的"无法区分。

### 3.3 为什么分成两次调用

| | 第 1 次调用 | 第 2 次调用 |
|---|---|---|
| 维度 | 情绪 · 情感 · 思维 · 立场 | 观点 · 意图 · 一致性 |
| 工具 | **不提供任何工具** | 全部 18 个工具 |
| 输入 | 画像 / 背景 / 记忆 / 平台现状 / 推荐流 / 定向互动 | 上述全部 + **第 1 次的完整原文** |
| 输出 | 只输出认知链文本 | 认知链文本 + tool call |

**理由**：如果同一次调用里既要求"推理情绪与立场"又提供动作工具，模型有很强的倾向
先确定要做什么动作，再倒推一套情绪与立场来支撑它。这样得到的推理是**合理化**而非
**决策依据**，用它做归因分析会得到系统性错误的结论。

拆成两次后，第一次调用在物理上看不到任何动作，只能做认知判断；第二次调用拿到的是
已经写定、无法修改的前提。**因果方向由调用结构保证**，不依赖提示模型保持诚实。

第一阶段原文通过 **user 消息**传入第二次调用（而非 system 消息）：
放在 system 中时模型容易把它当成一句背景说明而"看不到"具体结论，
进而从头重新推演第一阶段，浪费预算甚至产生自相矛盾的输出。

### 3.4 三档推理密度

`cognitive_chain.profile` 控制，**同一套代码**，都走两次调用：

| profile | 启用节点 | 节点构成 | 典型用途 |
|---|---:|---|---|
| `max` | 17 | 全部节点 | 完整推理链实验、案例深挖、机理分析 |
| `pro` | 13 | 情绪 `E1,E2`；情感 `M1,M2`；思维 `T1,T2`；立场 `S1,S3`；观点 `O2,O3`；意图 `I1,I2`；一致性 `Z1` | 长轮次、大规模运行 |
| `flash` | 7 | 每维度保留一个代表节点 + 一致性 | 冒烟验证、回归测试、超大规模试跑 |

节点选择在 `sim/chain/spec.py` 的 `PROFILES` 中声明。新增一档只需添加一个
`Profile`，无需改动 prompt 或解析逻辑。

### 3.5 输出契约与解析

模型被要求按固定格式输出，每个节点一行：

```
### 情绪
即时情绪：看到关税推高物价的报道，我第一反应是愤怒（强），同时有点担忧（中）。
```

解析器（`sim/chain/prompts.py` 的 `parse_chain`）需要兼容模型实际会混用的四种写法：

1. `节点名：内容` 独占一行
2. `### 维度 - 节点名` 或 `### 维度-节点名：内容`（节点名嵌在标题里）
3. `**节点名**` 单独成行，内容在下一行
4. `态度：…。主观规范：…。感知行为控制：…` 多个节点合并在同一段

解析结果分三种状态，**这个区分是健康度指标可信的前提**：

| 状态 | 含义 | 字段 |
|---|---|---|
| 显式写出 | 模型标出了节点名并给出内容 | `present=1, inherited=0` |
| 兜底填充 | 该维度的内容是一段没标节点名的散文，由整段文本兜底填充 | `present=1, inherited=1` |
| 缺失 | 该节点没有任何内容 | `present=0` |

实时监控页同时展示"有内容比例"与"显式标注比例"。
只看前者会把兜底内容误认为模型遵守了契约。

### 3.6 截断处理

开启模型内部推理后，输出可能因长度上限被截断。系统区分三种情形：

| 情形 | 判定 | 处理 |
|---|---|---|
| 正常 | 有内容，且节点齐全 | 采用 |
| 被截断 | `finish_reason == "length"`，且节点不全 | 追加一段格式指令**重问一次** |
| 推理未闭合 | 有 `<think>` 无 `</think>`，正文为空 | 视为截断，同上重问 |

重问时明确要求"不要写思考过程，直接从维度标题开始，每节点一句"。
这比重新解析同一段文本有效——后者在语法已损坏时必然同样失败。

## 四、动作工具层

### 4.1 工具清单（18 个）

| 类别 | 工具 |
|---|---|
| 内容互动 | `like_post` `dislike_post` `create_comment` `reply_to_comment` `share_comment` `like_comment` `dislike_comment` `create_post` |
| 关系 | `follow` `unfollow` |
| 只读探索 | `refresh` `trend` `search_posts` `search_user` `get_trending_comments` `get_post_detail` `get_user_profile` |
| 弃权 | `do_nothing` |

每个工具声明 `kind`（`read` / `write`）与 `max_calls_per_tick`。
只读工具用于多步探索（先看详情再评论），写工具改变平台状态。

### 4.2 三道守卫

**上下文守卫**——动作只能作用于该智能体本轮**确实看到过**的对象。
可见集合由 `refresh` 的返回动态构建，并在调用 `get_post_detail`、
`search_posts` 等只读工具后**动态扩展**，因此"先查看详情、再发表评论"
这条自然行为链可以走通。非法 ID 返回结构化错误，模型可在同一循环内改正。

**内容质量守卫**——拦截把推理过程当成社交发言的行为。
模型有时会把认知链的中间结论直接写进评论正文（例如"我所在的分析圈层期待理性讨论，
这种群体压力会促使我……"）。这类内容一旦入库，整个仿真台就失去了可信度，
因此按元推理的用词特征拦截，并返回改写指引。

**幂等**——点赞、关注等写动作依靠数据库唯一约束与 `INSERT OR IGNORE` 实现幂等。
重复调用不产生副作用，因此模型在同一轮多次尝试同一工具是安全的。

### 4.3 工具循环

第二次调用进入循环：模型给出 tool call → 执行 → 把结果作为 `role=tool` 消息回灌 →
模型可继续调用。约束有三层：单次响应内的并行调用数上限、
单工具每轮调用上限、每轮工具调用总数上限（`max_tool_calls_per_tick`）。
一旦产生成功的写动作即结束循环，避免无意义地继续探索。

## 五、数据库

### 5.1 表清单

`sim/platform/schema.sql` 是唯一权威定义，共 **18 张表**，启动时幂等建全。

**认知链表（4 张）**

| 表 | 粒度 | 主键 |
|---|---|---|
| `agent_turn` | 每轮每智能体一行 | `(agent_id, tick)` |
| `agent_chain_step` | 每轮每智能体每节点一行 | `(agent_id, tick, node_key)` |
| `agent_tool_call` | 每次工具调用一行 | `(agent_id, tick, call_order)` |
| `agent_interaction` | 每轮每智能体每条定向互动一行 | `(agent_id, tick, interaction_id)` |

**平台表（12 张）**

| 表 | 作用 |
|---|---|
| `user` | 智能体与外部作者的账号信息、画像、关注计数 |
| `post` | 帖子（含话题帖与语料导入帖） |
| `comment` | 评论与回复（自引用 `parent_comment_id`） |
| `post_like` / `post_dislike` | 帖子赞踩，唯一约束保证幂等 |
| `comment_reaction` | 评论赞踩（`kind` 区分方向） |
| `follow` | 关注关系，唯一约束保证幂等 |
| `comment_share` | 评论转发 |
| `rec` | 每轮每人的推荐快照（含分数与排名） |
| `trace` | 平台动作流水 |
| `intervention` | 定向互动记录 |
| `campaign_target` | 干预实验的目标名单 |

**运行元信息（2 张）**

| 表 | 作用 |
|---|---|
| `sim_meta` | 键值对：话题、规模、档位、模型、语料规模等 |
| `sim_tick_stat` | 每轮统计，是实时监控页的数据源 |

### 5.2 `agent_turn` 字段

这是核心宽表，按"看到 / 想到 / 做到"三段组织：

| 分组 | 字段 | 含义 |
|---|---|---|
| 状态 | `is_active` `status` `error_text` | 是否被激活、执行状态、失败原因 |
| ① 看到 | `feed_post_ids` `feed_trending_ids` `interaction_ids` | 本轮推荐流 / 热门评论 / 定向互动的 ID 列表（JSON） |
| ② 想到 | `thought_text` | 两阶段合并的完整原文，可直接引用 |
| | `stage1_text` `stage2_text` | 两阶段各自的原文 |
| | `chain_steps_json` | 节点级结构化结果（含缺失节点清单） |
| ③ 做到 | `actions_json` | 全部工具调用及结果 |
| | `primary_action` `primary_target_id` | 主动作及其对象 |
| | `reason` | 行为理由（意图维度首句，限长 140 字） |
| 元信息 | `profile` `stage1_ms` `stage2_ms` `prompt_tokens` `completion_tokens` `model` | 档位、耗时、token、模型名 |

**只存 ID、正文按需回查**是有意的设计：一条帖子可能被成百上千个智能体看到，
把正文冗余进每个 turn 会让库体积爆炸。分析时用 `post_id` 关联 `post` 表取回正文。

### 5.3 关键设计取舍

**思考原文与结构化节点都存**。`thought_text` 保留完整原文供阅读与引用，
`chain_steps_json` 与 `agent_chain_step` 保留节点级结构供统计与建模。
只有原文则难以量化，只有结构则丢掉了推理的语境。

**暴露缺失而不填补**。每个节点都有显式的 `present` / `inherited` 标记。
系统不会为了让统计好看而补默认值——那会让健康度指标失去意义。

**理由字段只做索引**。`reason` 是意图维度的首句摘要，完整推理在认知链里。
把长文本同时写进两个字段会造成不一致。

**同事务但错误边界独立**。认知链写入与平台状态写入在同一事务内保证一致，
但认知链写入失败不会导致平台状态回滚——两者各自记录错误。

### 5.4 schema 迁移

`db.py` 中的 `_migrate()` 在每次建表后执行，按 `PRAGMA table_info` 检查并补齐后加的列。
这样旧运行库无需重建即可继续使用。

## 六、推荐与可见性

推荐打分是**预取式**的：一次性把用户、帖子、关注关系、历史曝光读入内存，
打分阶段不再访问数据库。

| 特征 | 权重 | 说明 |
|---|---:|---|
| `hot` | 0.20 | 净赞数取对数 + 评论数，压缩长尾后归一化 |
| `time` | 0.15 | 基于仿真时钟的指数衰减（半衰期 12 仿真小时） |
| `follow` | 0.30 | 是否关注了作者 |
| `interest` | 0.20 | 智能体关注话题的关键词与帖子正文的重合度 |
| `persona` | 0.10 | 人设文本与帖子正文的字符二元组重叠度 |
| `random` | 0.05 | 探索项，避免排序完全确定 |

已看过的帖子乘 `seen_penalty`（默认 0.35）而非直接排除：
语料规模有限时需要允许重复曝光，但要让新内容优先。

**时钟是唯一权威**。`time` 特征使用 `SimClock` 的沙盒时间戳，
tick 与时间的映射由配置 `clock_step_minutes` 决定。
推荐结果连同分数与排名写入 `rec` 表，因此事后可以复盘"当时为什么推给它这条"。

可见性由 `refresh()` 决定：从本轮推荐中采样、合并关注流、挂载评论树。
返回的帖子与评论会被注册进该轮工具的可见集合，形成"看到什么 → 能对什么操作"的闭环。

## 七、实时监控页

### 7.1 架构

监控页运行在**独立进程**中，通过只读连接访问同一个 SQLite 库（WAL 模式支持读写并发）。
选择独立进程而非线程的原因有两点：仿真主循环长期占用事件循环；
以及仿真结束后用户仍需要能打开页面复盘已完成的运行。

后端只有标准库 `http.server`，提供六个只读接口：

| 接口 | 内容 |
|---|---|
| `/api/overview` | 运行概览与逐轮统计 |
| `/api/activities?tick=` | 某一轮的思考与动作流 |
| `/api/chain-health?tick=` | 节点写出率。每个节点返回两组口径：`present`/`rate`（有内容）与 `explicit`/`explicit_rate`（显式标注） |
| `/api/tool-stats?tick=` | 动作分布与失败数 |
| `/api/turn?agent_id=&tick=` | 单条记录详情（含看到的帖子正文）。`chain.steps[]` 中每步带 `inherited` 布尔字段 |
| `/print/turn?agent_id=&tick=` | 打印排版的 HTML 页面，供导出 PDF 使用（见 7.4） |

`/api/stream` 是 SSE 端点，推送四类事件：
`snapshot`（概览）、`activity`（一条思考与动作）、`chain`（节点写出率）、
`tools`（动作分布）。

### 7.2 轮次导航与回放

工具栏提供 `◀ / 轮次下拉 / ▶ / ▶▶ 自动回放`，可在仿真结束后逐轮回看历史。

关键在于**实时流与回放视图解耦**：进入回放时页面记录一个"回放游标"，
SSE 事件照常接收并累积到缓冲，但只在游标位于最新轮次时才追加到活动流。
因此回放期间到达的新事件不会打断阅读；顶部提示条与「回到最新」按钮负责
把游标重置回最新轮次并释放缓冲。键盘 `←` `→` 绑定为切换轮次。

### 7.3 URL 深链与静态快照

页面状态映射到 URL 查询参数，便于分享与嵌入：

| 参数 | 作用 |
|---|---|
| `agent` + `tick` | 直接打开某条记录并弹出详情侧栏 |
| `tab` | 定位详情侧栏的某个分区（`seen` / `chain` / `actions` / `raw`） |
| `no_stream=1` | 不建立 SSE 长连接、也不轮询，只做一次 REST 加载 |

打开记录与切换分区时会同步 URL（`history.replaceState`），因此任何时候
复制地址栏都能复现当前视图。

`no_stream=1` 是为**离线场景**准备的：嵌入离线报告、生成归档截图，
或在禁止长连接的代理后面查看。文档中的界面截图即由该模式生成——
headless 浏览器在有长连接时不会认为页面"已加载完成"，去掉 SSE 后
才可以用 `--virtual-time-budget` 稳定截取。

### 7.4 详情阅读与导出 PDF

活动卡片上的「查看完整记录」打开宽侧栏，按固定四段组织：

```
看到的内容  →  认知链  →  实际动作  →  两阶段原文
```

顺序即因果顺序，便于顺着一条记录读下来回答"它为什么这么做"。

「导出 PDF」**不使用 PDF 生成库**，而是由服务端渲染一张打印友好的 HTML
（`GET /print/turn`），再用浏览器自带的打印功能输出。理由：

* 正文是中文，在 Python 端生成 PDF 需要内嵌 CJK 字体，字体的体积与授权
  都是额外负担；
* 浏览器自带完整的中文字体栈与成熟的分页控制，输出质量更好；
* 不引入任何新的运行时依赖。

该路由返回的页面会内联一份打印样式（分页控制、去除交互元素），
并在加载后自动唤起打印对话框，用户选择"另存为 PDF"即可保存。

### 7.5 前端约定

* 全中文界面，无外部 CDN 依赖，可离线运行。
* 通过 `EventSource` 增量渲染，新增卡片头插，避免整块重排。
* 首帧先推送**当前轮**的活动（页面默认只看当前轮，先推历史轮会让首屏看起来是空的）。
* 六个认知维度各有固定主题色，集中用于维度标签与节点标记。
* 认知链健康度按维度分组，并把缺失或标注不完整的节点优先排到前面——
  异常项应当自己浮现，而不是让使用者逐个比对百分比。

### 7.6 派生字段的离线刷新

`agent_turn.reason` 是从认知链某节点摘取首句得到的**派生索引字段**，
完整推理始终保存在 `agent_chain_step` 与两阶段原文里。因此调整取值策略后，
可以用 `scripts/repair_reason.py` 离线重算，不必重跑仿真：

```bash
python scripts/repair_reason.py --db runs/<运行>.db           # 预览
python scripts/repair_reason.py --db runs/<运行>.db --apply   # 写入
```

这是把"完整数据"与"派生索引"分开存储带来的直接好处：派生层可以随时按新策略
重建，而原始推理不受影响。

## 九、已知限制

1. **语料规模是主要瓶颈**。示例数据含 2683 条帖子、283 位发言者，
   其中 58 位属于 300 人参与池（其余为池外语料作者）。
   大规模长轮次运行会显著提高帖子复用率；系统在收尾报告中打印实际复用倍数，
   建议把它作为仿真健康度的一个观察项。
2. **token 消耗较高**。开启内部推理后，单轮（两次调用，含可能的截断重问）
   约 10k token。降低消耗的手段：切到 `flash` 档、缩短 `memory_rounds`、
   减少 `refresh_post_count`。
3. **单轮延迟约 20–75 秒**，主要来自模型生成时间。提高并发端点数量可近线性改善。
4. **依赖支持 tool call 的推理服务**。动作层完全建立在 function calling 之上，
   不支持工具调用的模型无法运行。
5. **认知链是提示词层面的实现，不是微调**。因此认知维度的表达质量受基座模型能力
   影响；换用不同模型时需要重新观察节点写出率与内容质量。
